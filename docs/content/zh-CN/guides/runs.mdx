**运行**页面按提交时间从新到旧列出作业在集群上的每一次运行。作业提交到服务端时会创建一次运行（`POST /api/v1/runs`，见
[在集群上运行作业](../operations/server#在集群上运行作业)）。在没有配置 Master 的服务端上，提交的运行会立即以 `PF-CLUS-0015` 失败，并作为失败的运行列出。

<Screenshot name="runs" alt="运行页面" />

## 列表

| 列 | 含义 |
|---|---|
| 作业 | 作业名称，以及运行 ID 的前几个字符 |
| 状态 | **排队中**、**运行中**、**取消中**、**等待重试**、**暂停中**、**已暂停**、**成功**、**失败**、**超时**或**已取消** |
| 提交时间 | 运行提交的时间，按浏览器的时区显示 |
| 耗时 | 从开始到结束；运行中时计算到当前 |
| 读取、写入 | Source 读取和 Sink 写入的行数，截至运行指标的最近一次采样（默认每 10 秒一次）；第一次采样之前显示短横线 |
| 错误 | 未成功的运行的错误码；鼠标悬停或聚焦可以看到消息，也可以在[错误码](./error-codes)页面中查找 |

页面打开期间每两秒向服务端查询一次；浏览器标签页被隐藏时停止查询，放在后台的页面不会产生开销。

## 查找运行

在列表上方选择状态分组：

| 分组 | 状态 |
|---|---|
| 全部 | 所有运行 |
| 进行中 | 排队中、运行中、取消中、等待重试、暂停中、已暂停 |
| 成功 | 成功 |
| 失败 | 失败、超时 |
| 已取消 | 已取消 |

在搜索框中输入作业名称，只看该作业的运行；名称需要完全一致。两个筛选条件都在地址中（`/runs?state=failed&job=orders-daily`），
因此筛选后的列表可以收藏和分享。超过 50 个运行时，列表下方有**上一页**和**下一页**按钮。

## 单次运行

在列表中点击作业名称即可打开这次运行。页面顶部显示运行 ID、提交时间、开始时间、结束时间、耗时，未成功的运行还会显示错误。
地址（`/runs/<id>`）可以分享；运行不存在时页面会说明。运行未结束时，页面每两秒刷新一次。

<Screenshot name="run-detail" alt="运行的概览" />

运行状态旁边是它当前允许的操作；每个操作都会先在对话框中确认，服务端拒绝时对话框保持打开并显示错误：

| 状态 | 操作 |
|---|---|
| 运行中 | **暂停**用 savepoint 停止运行（名称可选）：先进入*暂停中*，Sink 提交完成后进入*已暂停*，不再占用 Slot；savepoint 失败时运行继续读取。**Savepoint** 做一次 savepoint，运行继续。**取消**停止运行，可以填写原因，原因与运行一起保存 |
| 已暂停 | **继续**从 savepoint 重新启动运行，仍是同一次尝试。**取消** |
| 排队中 | **取消** |
| 失败、超时、已取消 | **重试**开始下一次尝试，不受 `env.retry` 限制：从最近完成的 checkpoint 或从头开始；没有完成的 checkpoint 时从头开始 |

<Screenshot name="run-pause" alt="暂停运行" />

**概览**标签页：

| 部分 | 内容 |
|---|---|
| 行数 | 读取和写入的行数及当前速率、读取器和写入器之间的行数（传输中）和跳过的坏行；已读完的分片占全部分片的比例作为进度 |
| 等待 | Task 的时间中用于等待的比例：读取器等待目标端、写入器等待源端、等待限流、等待网络缓冲 |
| 瓶颈 | 限制运行速度的因素、依据的指标和建议，来自[运行分析](../concepts/plan-and-explain#运行分析)；运行中按最近 10 秒判断，已结束按整个运行判断 |

**指标**标签页（`/runs/<id>?tab=metrics`）根据服务端对运行指标的采样绘制读写速率和行数变化，并列出计划中每个节点的输入和输出行数。
有两次采样后才显示图表；服务端默认每 10 秒采样一次（`pipeforge.master.metrics-interval`）。

<Screenshot name="run-metrics" alt="运行指标随时间的变化" />

**执行计划**标签页（`/runs/<id>?tab=plan`）把运行的作业画成图，并在图上标出数据：

- 每个节点下方显示它已输出的行数（Sink 为已接收的行数）和当前速率
- 连线的粗细对应其起点节点的速率，繁忙的路径一目了然
- [运行分析](../concepts/plan-and-explain#运行分析)认定为瓶颈的节点带有警示边框和标记；结论、依据和建议显示在图的下方

选择一个节点可以查看它的输入和输出行数、过滤掉的行、展开新增的行、跳过的坏行、输入和输出字节，以及输入和输出速率。
选中的节点记录在地址中（`/runs/<id>?tab=plan&node=warehouse`）。节点的计数是它所有并行子任务的合计。
每个节点的繁忙程度和等待位置目前还没有按节点统计；概览中显示的是整个运行的等待情况。

<Screenshot name="run-plan" alt="运行的执行计划，瓶颈已标出" />

**分片**标签页（`/runs/<id>?tab=splits`）显示每个 Source 的进度：已分发的分片中读完了多少，以及每个分片由哪个读取器（子任务）负责、是否已读完。
运行开始后才会出现分片；不分片的 Source 没有分片。

<Screenshot name="run-splits" alt="运行的分片" />

**Checkpoint** 标签页（`/runs/<id>?tab=checkpoints`）从新到旧列出运行在各次尝试中的 [checkpoint](../concepts/checkpoint) 和 savepoint：

- 顶部是最近完成的 checkpoint，以及已完成、savepoint 和失败的数量
- 每一项显示编号、类型、状态、触发原因（`PERIODIC`、`SAVEPOINT`、`PAUSE`、`FINISH` 等）、触发时间、耗时、各 Task 中最长的 barrier 对齐耗时、大小，
  以及 savepoint 的名称或失败的原因
- 点击编号查看每个 Task 的部分：快照让它停顿了多久、上传和对齐各用了多久、状态有多大；选择记录在地址中，没有选择时显示最近完成的一项

运行进行时，**做 savepoint** 会做一次 savepoint（名称可选），完成后显示它的编号和目录；savepoint 会一直保留到手动删除。对齐耗时长说明 Task 的输入有反压；
失败的 checkpoint 会说明哪些 Task 没有应答。

<Screenshot name="run-checkpoints" alt="运行的 checkpoint" />

**日志**标签页（`/runs/<id>?tab=logs`）经由 Master 从 Task 所在的 Worker 读取日志：

- 在菜单中选择 Task（顶点、子任务和重试次数，以及 Worker 和状态）；选择记录在地址中
- 最低级别和查找文本在 Worker 上过滤日志，因此对任意大小的日志都有效；匹配的文本会被标出
- 先显示日志末尾的 64 KB，之后每两秒追加新日志，直到 Task 结束；视图位于末尾时自动滚动，向上滚动时停止，
  滚回末尾或点击**跟随**后继续
- **下载**保存完整的、未过滤的日志，最多 64 MB

日志按级别着色，异常堆栈的各行沿用所属日志条目的级别。
