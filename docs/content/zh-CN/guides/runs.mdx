**运行**页面按提交时间从新到旧列出作业在集群上的每一次运行。作业提交到服务端时会创建一次运行（`POST /api/v1/runs`，见
[在集群上运行作业](../operations/server#在集群上运行作业)）。在没有配置 Master 的服务端上，提交的运行会立即以 `PF-CLUS-0015` 失败，并作为失败的运行列出。

<Screenshot name="runs" alt="运行页面" />

## 列表

| 列 | 含义 |
|---|---|
| 作业 | 作业名称，以及运行 ID 的前几个字符 |
| 状态 | **排队中**、**运行中**、**取消中**、**成功**、**失败**、**超时**或**已取消** |
| 提交时间 | 运行提交的时间，按浏览器的时区显示 |
| 耗时 | 从开始到结束；运行中时计算到当前 |
| 读取、写入 | Source 读取和 Sink 写入的行数，截至运行指标的最近一次采样（默认每 10 秒一次）；第一次采样之前显示短横线 |
| 错误 | 未成功的运行的错误码；鼠标悬停或聚焦可以看到消息，也可以在[错误码](./error-codes)页面中查找 |

页面打开期间每两秒向服务端查询一次；浏览器标签页被隐藏时停止查询，放在后台的页面不会产生开销。

## 查找运行

在列表上方选择状态分组：

| 分组 | 状态 |
|---|---|
| 全部 | 所有运行 |
| 进行中 | 排队中、运行中、取消中 |
| 成功 | 成功 |
| 失败 | 失败、超时 |
| 已取消 | 已取消 |

在搜索框中输入作业名称，只看该作业的运行；名称需要完全一致。两个筛选条件都在地址中（`/runs?state=failed&job=orders-daily`），
因此筛选后的列表可以收藏和分享。超过 50 个运行时，列表下方有**上一页**和**下一页**按钮。

## 单次运行

在列表中点击作业名称即可打开这次运行。页面顶部显示运行 ID、提交时间、开始时间、结束时间、耗时，未成功的运行还会显示错误。
地址（`/runs/<id>`）可以分享；运行不存在时页面会说明。运行未结束时，页面每两秒刷新一次。

<Screenshot name="run-detail" alt="运行的概览" />

**概览**标签页：

| 部分 | 内容 |
|---|---|
| 行数 | 读取和写入的行数及当前速率、读取器和写入器之间的行数（传输中）和跳过的坏行；已读完的分片占全部分片的比例作为进度 |
| 等待 | Task 的时间中用于等待的比例：读取器等待目标端、写入器等待源端、等待限流、等待网络缓冲 |
| 瓶颈 | 限制运行速度的因素、依据的指标和建议，来自[运行分析](../concepts/plan-and-explain#运行分析)；运行中按最近 10 秒判断，已结束按整个运行判断 |

**指标**标签页（`/runs/<id>?tab=metrics`）根据服务端对运行指标的采样绘制读写速率和行数变化，并列出计划中每个节点的输入和输出行数。
有两次采样后才显示图表；服务端默认每 10 秒采样一次（`pipeforge.master.metrics-interval`）。
