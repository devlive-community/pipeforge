[快速开始](./quickstart)在 `pipeforge` 进程内运行作业。这里同一个命令把作业发送到集群：Master 负责规划并放置 Task，Worker 运行 Task，
服务端保存运行记录，命令与服务端通信。所有进程都运行在一台机器上；多台机器的部署见[部署](../operations/deployment)。

## 启动集群

在解压后的发行版目录中，使用 Java 21：

```bash
export PIPEFORGE_CLUSTER_TOKEN="$(openssl rand -hex 32)"
bin/pipeforge-standalone.sh start
```

standalone 进程在一个进程中同时运行 Master 和 Worker；Master 监听 6123 端口。然后启动服务端，并把它指向 Master：

```bash
java -jar lib/server/pipeforge-server-*-exec.jar \
  --pipeforge.master.address=localhost:6123 \
  --pipeforge.master.token="$PIPEFORGE_CLUSTER_TOKEN"
```

服务端监听 `http://127.0.0.1:8080`，这也是 `pipeforge` 命令默认连接的地址；其他地址用 `--server` 或 `PIPEFORGE_SERVER` 指定。
确认集群已就绪：

```bash
curl -s http://127.0.0.1:8080/api/v1/cluster
```

返回中列出 Master 和一个 Worker 及其 Slot。

## 运行作业

编写一个需要运行一会儿的作业 `orders.yaml`：

```yaml
version: 1
name: orders-demo
source:
  - id: orders
    type: fake
    columns:
      - id INT64 NOT NULL
      - amount DECIMAL(10, 2)
    rows: 5000000
    splits: 8
sink:
  - { id: out, type: blackhole }
```

```bash
bin/pipeforge run orders.yaml
```

不带 `--local` 时，命令把作业提交到服务端，在标准错误中输出运行 ID，运行期间显示进度，结束时输出摘要：

```text
Submitted run 3d0f9c1a-5b7e-4c2a-9f10-6a8e2b4c7d01 to http://127.0.0.1:8080.
Job orders-demo SUCCESS in 4.1s: read 5,000,000 rows, wrote 5,000,000 rows (1,219,512 rows/s)
```

时间和速率每次会有所不同。退出码对应运行的结束方式：0 成功，4 失败，5 超时（`--timeout` 到时会取消运行），8 已取消。按 Ctrl-C 只停止命令，不停止运行。
`--detach` 只提交作业并输出运行 ID，适合稍后再跟踪运行的脚本。

## 跟踪运行

| 命令 | 显示 |
|---|---|
| `pipeforge run status <run>` | 状态、已读完的分片和剩余时间、行数和速率、瓶颈及建议、错误 |
| `pipeforge run watch <run>` | 每两秒刷新一次状态和各节点，直到运行结束；输出不是终端时每两秒输出一行 JSON。退出码与 `run` 相同 |
| `pipeforge run logs <run> [--task orders[0]] [-f] [--level WARN] [--grep 文本]` | 经由服务端从 Worker 读取的 Task 日志；`-f` 跟随一个 Task 直到它结束 |
| `pipeforge run metrics <run>` | 运行的指标和每个节点的行数 |
| `pipeforge run analyze <run>` | [运行分析](../concepts/plan-and-explain#运行分析)：速率、等待、瓶颈和建议 |
| `pipeforge run cancel <run> [--reason 文本]` | 要求运行停止；在终端上会先询问，其他情况下需要 `--yes` |

所有命令加 `-o json` 时输出 JSON，字段与 [REST API](../reference/api) 一致。运行不存在时以 6 退出并报告 `PF-CONF-0010`；
无法连接服务端时以 1 退出并报告 `PF-CLUS-0008`。[Web UI](../guides/runs) 中显示的是同样的运行。

## 停止集群

按 Ctrl-C 停止服务端，然后：

```bash
bin/pipeforge-standalone.sh stop
```

运行记录保存在服务端的[元数据库](../operations/metastore)中，默认位于 `~/.pipeforge/metastore`。
