## 只需一个依赖

插件只依赖 `org.devlive.pipeforge:pipeforge-api`。它不依赖任何引擎；除 JDK 之外只带来 `pipeforge-common`（错误码）
和 JSpecify（空值注解）。因此同一个插件可以运行在 PipeForge 引擎上，之后也可以运行在 Flink 或 Spark 上。

```xml title="pom.xml"
<dependency>
  <groupId>org.devlive.pipeforge</groupId>
  <artifactId>pipeforge-api</artifactId>
  <version>0.1.0</version>
  <scope>provided</scope>
</dependency>
```

## Source

一个 Source 有一个负责发现分片的 **Enumerator** 和多个并行读取分片的 **Reader**。Reader 采用拉模式：读完一个分片后再申请下一个，
因此快的 Reader 会多干活。批处理、流处理和 CDC 的 Source 实现同一套接口，区别只在 `boundedness()` 和分片。

```java
public interface SourceReader<SplitT extends SourceSplit> extends AutoCloseable {
    void start() throws Exception;
    void addSplits(List<SplitT> splits);
    void notifyNoMoreSplits();
    PollStatus pollNext(ReaderOutput output) throws Exception; // 不能长时间阻塞
    List<SplitT> snapshotState(long checkpointId);           // 带进度的分片
}
```

没有数据时 `pollNext` 返回 `NOTHING_AVAILABLE` 而不是阻塞，由引擎负责退避后再次读取。分片状态记录已经交给下游的位置，
因此恢复后的 Reader 能从这里精确继续。

## Transform 与 Sink

`Transform` 在计划阶段推导输出表（`transformSchema`），运行时逐行处理（`process(row, out)`）；Schema 变更由
`transformSchemaChange` 处理。

`Sink` 在计划阶段校验输入表并创建 Writer。Writer 负责 `write`、`flush`，需要 exactly-once 时在 `prepareCommit`
中产生待提交物，由 `SinkCommitter` 或 `GlobalCommitter` 在 checkpoint 完成后提交。

## 表达式

需要用户写表达式的组件（例如字段映射的 `expr`、过滤条件）不需要自带解析器：`context.expressions()` 提供引擎的[表达式语言](../concepts/expressions)，
类型规则和函数与 PipeForge 其他地方完全一致。

```java
// 计划阶段，在工厂中：读取数据之前就知道类型
ExpressionCompiler expressions = factoryContext.expressions();
ExpressionInfo info = expressions.analyze(List.of("amount * qty"), table.columns()).get(0);
info.type();           // DECIMAL(21, 2)

// 运行时，在 Transform.open 中：每个并行实例一个求值器
RowEvaluator evaluator = context.expressions().compile(List.of("amount * qty"), columns, OnError.DIRTY);
Object[] values = new Object[evaluator.size()];
evaluator.evaluate(row, values);
```

- 无法解析或类型检查不通过的表达式会让计划失败，错误码 `PF-PLAN-0007`，带出错的行、列，作用范围中带节点。
- 一起编译的表达式共享公共子表达式。求值器不是线程安全的。
- `OnError` 决定求值失败时的处理（`dirty`、`null` 或 `fail`），请把它作为组件的 `on-error` 选项提供给用户。
- `RUN_START_TIME()` 在一次运行的所有 Task 中都相同，日期时间按作业的 `env.timezone` 计算。

## 函数

函数是带注解的 Java 方法。内置函数就是这样声明的，函数插件也将使用 `api.function` 中的同一套契约，因此插件只依赖
`pipeforge-api`。安装函数插件的能力在后续版本中提供；下面是函数插件将要遵循的契约。

```java
public final class CardFunctions {

    @ScalarFunction(name = "mask_card")                // 登记在插件的命名空间中：acme.mask_card
    public static String maskCard(String cardNo) {     // 参数为 NULL 时直接返回 NULL，不调用方法
        return "****" + cardNo.substring(Math.max(0, cardNo.length() - 4));
    }

    @ScalarFunction(name = "with_rate")
    @Returns("DECIMAL(18, 2)")                         // Java 类型不够精确时声明逻辑类型
    public static BigDecimal withRate(@Param("DECIMAL(16, 2)") BigDecimal amount, int rate) {
        return amount.multiply(BigDecimal.valueOf(rate));
    }

    @ScalarFunction(name = "local_day")
    public static LocalDate localDay(FunctionContext context, Instant at) {  // 由引擎注入上下文
        return at.atZone(context.timeZone()).toLocalDate();
    }
}
```

| 契约 | 含义 |
|---|---|
| `@ScalarFunction(name, deterministic = true, nullOnNull = true)` | 标在公开方法上；同名的方法是重载。`nullOnNull` 为真时任一参数为 NULL 直接返回 NULL，不调用方法；为假时参数必须是引用类型。所有重载都确定时函数才是确定的 |
| `@Returns("…")` | 结果类型：例如 `DECIMAL(18, 2)` 这样的类型；`$n` 表示与第 n 个参数（从 0 开始）同类型；`$n:integral` 表示该 DECIMAL 参数去掉小数位。不写时由 Java 返回类型推导 |
| `@Param("…")` | 参数的类型；参数会被转换为恰好这个类型，放不下的参数在计划阶段被拒绝。不写时，`BigDecimal` 或 `String` 参数原样接受任意 DECIMAL 或 STRING |
| `FunctionContext` | 作为第一个参数：作业时区、运行开始时间、处理时间、作业信息，以及作业为函数配置的参数 |
| `FunctionLifecycle` | 实例方法需要实现它：每个并行实例创建一个对象，在第一行之前调用 `open(context)`，最后一行之后调用 `close()`；失败时报告 `PF-PLUG-0007` |

Java 类型与逻辑类型的对应关系和行中一致：`String` → `STRING`、`int` → `INT32`、`long` → `INT64`、`double` → `FLOAT64`、
`boolean` → `BOOLEAN`、`BigDecimal` → `DECIMAL`、`LocalDate` → `DATE`、`LocalTime` → `TIME`、`LocalDateTime` → `TIMESTAMP`、
`Instant` → `TIMESTAMP_LTZ`、`byte[]` → `BYTES`。

## 选项

每个工厂用 `OptionRule` 声明自己的选项和选项之间的规则。同一份规则用于计划阶段的校验、UI 表单的渲染和插件文档的生成。

```java
static final Option<String> URL = Options.key("url").stringType().noDefault().withDescription("JDBC URL");
static final Option<Integer> FETCH_SIZE =
        Options.key("fetch-size").intType().defaultValue(1000).withRange(1, null).withGroup("throughput");

@Override
public OptionRule optionRule() {
    return OptionRule.builder()
            .required(URL)
            .optional(FETCH_SIZE)
            .exclusive(QUERY, TABLE)                                  // 二者恰好设置一个
            .conditional(SPLIT_STRATEGY, Strategy.RANGE, SPLIT_COLUMN) // 选了 RANGE 时 split-column 必填
            .nativeNamespaces("jdbc.properties")                      // 原样透传，不做校验
            .build();
}
```

选项类型有 `stringType`、`intType`、`longType`、`doubleType`、`booleanType`、`durationType`（`30s`、`5m`）、`enumType`、
`listType`（普通值的列表，或逗号分隔的字符串）、`mapType`（嵌套的键，也可以写成点号形式）和 `objectListType`：由普通值组成的对象的列表，
例如字段映射的条目（`[{ from: id, to: order_id }]`），读取为 `List<Map<String, String>>`。

校验时，缺少的选项报 `PF-CONF-0001`，不合法的取值（类型、范围、互斥组、带拼写建议的未知选项）报 `PF-CONF-0002`。
敏感选项的取值在错误信息中会被遮蔽。

## 工厂

工厂通过 `java.util.ServiceLoader` 从插件的类加载器中发现。工厂提供 `identifier()`（作业中使用的名称）和 `optionRule()`，
并根据 `FactoryContext` 创建组件：其中包含已校验的选项、原生配置、作业信息和上游表结构。

## 稳定性

每个公开类型都带有稳定性注解：

| 注解 | 承诺 |
|---|---|
| `@Stable` | 同一主版本内二进制兼容 |
| `@Evolving` | 可能在次版本中调整 |
| `@Internal` | 不做承诺，插件不应使用 |

运行时可以通过 `ApiVersion.current()` 获取 API 版本；插件声明自己构建时的主版本（`ApiVersion.descriptorForm()`，例如 `0.x`），引擎拒绝加载为其他主版本构建的插件。

接口新增的方法一律提供默认实现。构建时用 japicmp 与上一个发布版本比较，出现不兼容改动即失败；另有测试检查每个公开类型都带有其中一个注解。
