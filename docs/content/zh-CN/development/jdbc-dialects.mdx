关系型数据库的插件共用 **`connector-jdbc`**，这是每个插件都打包在自己插件包中的一个库。它按分片读取表、按批写入行，并把
数据库错误转换为 PipeForge 的错误；各数据库之间不同的部分是**方言**。数据库插件实现一个方言，用它创建基础库中的 Source 和
Sink，其他功能都可以直接使用。

## 基础库做了什么

| 部分 | 内容 |
|---|---|
| 连接 | 用插件 ClassLoader 中的驱动打开连接，按 `driver` 或按 URL 查找；驱动属性依次合并方言默认值、`username` 和 `password`、`jdbc.properties.*`；方言控制的属性会被拒绝（`PF-CONF-0003`） |
| Schema | 根据 JDBC 元数据描述表（列、类型、是否可空、主键），数据库把名称存为大写或小写时也能找到；不执行即可描述 `query` 的结果 |
| 表 | 一张 `table`、一个 `query`，或者限定名（`db.table`）匹配 `tables.include` 中某个正则表达式、且不匹配 `tables.exclude` 的所有表；这些表在规划作业和作业启动时从元数据中查找，系统 Schema 除外；每一行都带有所属表的名称 |
| 分片 | 每张表单独切分，所有表的分片共用一个队列。`split.mode: range` 时，探测分片列（`split.column`，否则为只有一个整数列的主键）的 MIN 和 MAX，切成 `split.count` 个范围，第一个和最后一个范围不设边界，另加一个读取 NULL 的分片；否则以及 `query` 时只有一个分片。Reader 每次拉取一个分片，读得快的 Reader 读得多 |
| 读取 | 用 `fetch-size` 流式读取每个分片；方言无法读取的值让这一行成为坏行，Reader 继续读后面的行 |
| 续传 | 范围分片按分片列 `ORDER BY` 读取，只在分片列的值变化处结束一次读取，因此 checkpoint 记录的是最后读到的值；恢复后的分片加上 `AND <分片列> > ?`（设计 06 第 5 节）。同一个值超过 `resume.max-group-rows` 行时，checkpoint 可能落在这些行之间，这个值会再读一次。整张表、query 和 NULL 分片从头续传 |
| 写入 | 每批 `batch-size` 行，每批一个事务。因暂时性原因失败的批次回滚后，在 `retry-backoff` 之后重试 `max-retries` 次，等待时间逐次加倍；因数据失败的批次回滚后对半拆分，直到每个坏行单独成批，坏行交给[脏数据策略](../concepts/dirty-data)，好的行照常写入 |
| 错误 | 连接、登录、超时和表不存在分别转换为 `PF-CONN-0001`–`0003`、`PF-AUTH-0001` 和 `PF-META-0001`，数据错误转换为坏行（`PF-DATA-0009`），其他错误为 `PF-SRC-0001` / `PF-SINK-0001` |

凭据不会出现在信息中：URL 显示时会去掉用户信息和密码参数。

## 方言 SPI

方言继承实现了 ANSI SQL 的 `AbstractJdbcDialect`，并覆盖自己数据库不同的部分：

| 方法 | ANSI 行为 | 何时覆盖 |
|---|---|---|
| `name()` | —（必须实现） | — |
| `quote(identifier)` | `"name"` | 数据库的引号不同，例如 `` `name` `` |
| `catalogAndSchema(table)` | `db.t` 中 `db` 为 Schema | 第一部分是 Catalog，例如 MySQL |
| `tableId(catalog, schema, table)` | `schema.table` | 元数据把表列在 Catalog 下 |
| `systemSchemas()` | `INFORMATION_SCHEMA` | 数据库还有其他系统 Schema，`tables.include` 不应选中它们 |
| `defaultProperties()` | 无 | 驱动需要特定设置，例如批量改写 |
| `controlledProperties()` | 无 | 某个属性会破坏写入事务或读取；需要给出原因 |
| `toDataType(column)` | 标准类型的 `java.sql.Types` | 数据库有自己的类型、无符号整数、JSON、数组 |
| `read` / `write` | 用 `java.time` 类型的 `getObject` / `setObject` | 驱动需要其他取值方法或转换 |
| `minMaxQuery`、`selectQuery`、`insertStatement` | ANSI SQL | 语法不同 |
| `prepareStreaming(connection, statement, fetchSize)` | 设置 fetch size | 驱动以其他方式流式读取，例如需要事务或特殊的 fetch size |
| `classify(error)` | 按 SQLState 类别：`08` 连接、`28` 登录、`22`/`23` 数据、`40001`/`40P01` 暂时性、`42S02`/`42P01` 不存在 | 驱动报告厂商错误码 |

方言是无状态、可序列化的。`GenericDialect` 就是 ANSI 方言本身，供没有专属方言的数据库使用。

## 方言

| 方言 | 模块 | 已验证 | 与 ANSI 的不同 |
|---|---|---|---|
| `jdbc`（`GenericDialect`） | `connector-jdbc` | H2 | 无 |
| `mysql` | `connector-mysql` | MySQL 8.0、8.4，Connector/J 8.4 | 反引号；`db.t` 中 `db` 是 Catalog；无符号整数放宽一级，`BIGINT UNSIGNED` 为 `DECIMAL(20, 0)`，`YEAR` 为 `INT16`，`BIT(n)` 为 `BYTES`，`TIMESTAMP` 为时间点；会话使用 UTC、批量改写、UTF-8；逐行流式读取；`allowLoadLocalInfile`、`allowUrlInLocalInfile` 和 `autoReconnect` 为受控键；按 MySQL 错误码分类；表按 Catalog 命名为 `库.表`，`mysql`、`sys`、`information_schema` 和 `performance_schema` 是系统库；Source 使用的方言（`MySqlDialect.forReading()`）还通过二进制协议读取（`useServerPrepStmts`），因为文本协议会丢失 `FLOAT` 的位数 |
| `postgres` | `connector-postgres` | PostgreSQL 14、16，PostgreSQL JDBC 驱动 42.7 | 双引号；`s.t` 中 `s` 为 Schema；`pg_catalog` 和 `pg_toast` 是系统 Schema；`timestamptz` 是时刻，`json`/`jsonb` 是 `JSON`；没有精度或超过 38 位的 `numeric` 为 `STRING`，精确保留包括 `NaN` 在内的值；`uuid`、`interval`、`money`、网络地址、位串、`xml` 和 `timetz` 读作文本；布尔、整数、浮点和文本的数组为 `ARRAY`；在事务中按 fetch size 流式读取；改写批次，文本参数不带类型发送（`stringtype=unspecified`），因此 `jsonb`、`uuid` 和枚举列可以接收文本；会加载类（`socketFactory`、`sslfactory` 等）或写文件（`loggerFile`）的属性是受控属性；按 PostgreSQL 的 SQLState 识别库不存在、关闭、连接过多和锁超时 |

## 接入插件

```java
public final class AcmeSourceFactory implements SourceFactory {
    static final JdbcDialect DIALECT = new AcmeDialect();

    @Override
    public String identifier() {
        return "jdbc-acme";
    }

    @Override
    public OptionRule optionRule() {
        return JdbcOptions.sourceRule().build(); // url、table | query、分片、jdbc.properties.*
    }

    @Override
    public JdbcSource createSource(FactoryContext context) {
        return new JdbcSource(JdbcSourceConfig.of(context.options(), DIALECT, context.nodeName()), DIALECT);
    }
}
```

Sink 的写法相同，使用 `JdbcOptions.sinkRule()`、`JdbcSinkConfig` 和 `new JdbcSink(config, DIALECT, context.inputTables())`。
插件自己的选项通过 `sourceRule(extra...)` 加入。

## 测试方言

针对数据库运行 testkit 的 Source 和 Sink 契约测试（见 [testkit](./testkit)）：连接器在 `options(table)` 中创建测试表，声明自己
支持的类型，并把 `split.mode: none` 和范围分片作为分片策略提供。`checkpoint` 用例组在分片读到中途时恢复 Reader，检查每一行恰好读一次；
`state-compat` 保证早期版本的 Reader 状态仍可读取：它要求时，请提交它写到 `src/test/resources/testkit-state/` 下的文件。Reader 会在方言的
`selectQuery` 之后追加 `ORDER BY` 和 `AND <分片列> > ?`，因此这条查询必须以 `WHERE` 子句结尾。再为方言的类型映射、SQL 和错误分类补充单元测试。基础库本身就是
这样用通用方言在 H2 上测试的。
