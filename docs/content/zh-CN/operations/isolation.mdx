作业共享集群中的 Worker：多个作业的 Task 运行在同一个 Worker 进程中，各自占用一个 Slot。一个作业不能拖垮其他作业，
因此每个 Task 都受到只让它自己失败或变慢的限制。

## 单行大小

Source 读取的每一行都按它在内存中的估算大小计量——对象头、引用以及各个值的内容，文本每个字符按两字节计。超过
`task.max-row-bytes`（默认 64MB）的行会让它的作业以 [`PF-DATA-0007`](../reference/errors#pf-data-0007) 失败，错误中给出节点、
表、大小和上限。被 Transform 变大的行在进入写缓冲之前会再检查一次；发给其他 Task 的行按编码后的大小检查。

目前整个作业失败；同一 Worker 上的其他作业继续运行。可以跳过或单独保存这类行的坏行策略会在后续版本中提供。

## Task 内存

每个 Task 对自己占用的内存记账：

| 占用者 | 计入的内容 |
|---|---|
| 写缓冲 | 等待 Sink 写线程写入的行，按估算大小 |
| 网络缓冲 | 它的输出和输入使用的缓冲，来自 Worker 的网络内存 |
| 分片队列 | 等待 Task 交给 Reader 的分片分配 |

写缓冲中等待的行受 `worker.memory.task` 限制：达到上限时，Reader 等待写线程写出一部分，这与写队列已满时的背压相同，
等待时间计入 `readerWaitMs`。没有行在等待时总会接收一行，因此超过这个上限的单行仍能通过。网络缓冲受[数据交换](../concepts/execution)
的配置限制；Task 会等待缓冲，而不会无限增长。

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `worker.memory.task` | 扣除网络内存后剩余堆的一半，按 Slot 平分，不少于 16MB | 一个 Task 为 Sink 保留的行最多占用的内存 |
| `task.max-row-bytes` | `64MB` | 单行大小上限 |
| `worker.memory.network` | 堆的 10%，64MB 到 1GB | 所有 Task 的网络缓冲 |

本地运行（`pipeforge run --local`）检查单行大小，但不限制 Task 内存。

## 堆守护

Task 内存限制的是 Task 为 Sink 保留的行，但一个作业仍可能用保存在别处的行占满 Worker 的堆。为了不让 Worker 内存溢出、
拖垮其上的所有作业，堆守护每秒检查一次堆，并找出在这个 Worker 上运行中的 Task 记账内存最多的运行：

1. 堆使用达到 `worker.heap-guard.pause-percent`（默认 85%）时，该运行的 Source Task 停止读取。已经读出的行继续写往 Sink，
   因此这个运行会释放内存，而其他运行照常读取。堆使用重新低于这条线后，它立即继续读取；如果占用最多的变成了另一个运行，
   则改为暂停那个运行。
2. 堆使用在 `worker.heap-guard.fail-percent`（92%）以上持续 `worker.heap-guard.fail-after`（10 秒）时，该运行在这个 Worker
   上的 Task 以 [`PF-RES-0002`](../reference/errors#pf-res-0002) 失败，错误中给出 Worker、运行和它占用的内存。这些 Task
   像被取消的 Task 一样停止并释放内存；其他运行继续。这是资源类错误，作业的[重启策略](../concepts/failure-handling)
   可能会重启它，有 checkpoint 时从最近的 checkpoint 恢复。

堆使用按已用除以最大堆计算，包括尚未回收的垃圾：垃圾回收器能够不断释放的堆不会在失败线以上停留十秒，真正被存活的行占满的堆才会。
堆已满但没有任何运行中的 Task 记账内存时，没有可以归咎的运行：Worker 记录一条警告，不做任何处理。每一次暂停、继续和失败都会记录在
Worker 日志中。

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `worker.heap-guard.enabled` | `true` | 是否运行堆守护 |
| `worker.heap-guard.pause-percent` | `85` | 堆使用达到这个百分比时，占用最多的运行停止读取 |
| `worker.heap-guard.fail-percent` | `92` | 堆使用达到这个百分比并持续 `fail-after` 后，该运行失败 |
| `worker.heap-guard.fail-after` | `10s` | 堆使用需要在 `fail-percent` 以上持续多久 |

暂停百分比不能高于失败百分比。本地运行没有堆守护。

## 插件代码

对插件的每次调用都以插件的 ClassLoader 作为线程上下文 ClassLoader。插件抛出的错误如果带有错误码则保留；否则插件有 `ErrorClassifier` 时由它转换（见[失败处理](../concepts/failure-handling)），再否则对 Source 归为
`PF-SRC-0001`、对 Sink 归为 `PF-SINK-0001`、对 Transform 归为 `PF-PLUG-0007`，并给出节点和当时的操作；插件需要却没有带上的类
（`NoClassDefFoundError` 等链接错误）也按同样方式报告，而不会让 Worker 停止。

**线程。** 插件从 Reader 或 Writer 上下文的 `threadFactory()` 获取的线程命名为 `plugin-<task>-<node>-<n>`，带有插件的
ClassLoader 和 Task 的日志，并且是守护线程。其中任何一个抛出未捕获的异常都会让 Task 失败。Task 结束时，引擎中断仍然存活的线程；
一秒后仍然存活的线程会在 Worker 日志中被报告为泄漏，并给出它停在哪里。用其他方式启动的线程不受跟踪。

**取消。** 被取消的 Task 会被唤醒，它的 Reader 和 Writer 会被要求停止阻塞的 IO。超过 `task.cancel-timeout` 仍未停止的 Task
会被中断线程；仍然不响应中断的 Task 在 `task.cancel-kill-timeout` 后被放弃：它以 [`PF-RES-0005`](../reference/errors#pf-res-0005)
失败，Slot 被释放，它的线程被报告为残留，并给出它停在哪里。Worker 上的其他作业继续运行。

| 配置项 | 文件 | 默认值 | 含义 |
|---|---|---|---|
| `task.cancel-timeout` | `master.yaml` | `30s` | 何时中断被取消的 Task 的线程；是 Master 运行的作业的默认值 |
| `task.cancel-kill-timeout` | `worker.yaml` | `3min` | 何时放弃不响应取消和中断的 Task |

本地运行在取消超时的两倍时放弃 Task。

## 磁盘配额

需要本地文件的 Reader 和 Writer 从上下文提供的工作目录中获取（`workDirectory()`，见 [API 概览](../development/api-overview)）。
一个运行的工作目录位于 `<worker.dir>/jobs/<run>/` 下，每个 Task 的每个节点一个；Task 结束时删除它的目录，运行在该 Worker 上的
最后一个 Task 结束时删除运行的目录，已停止的 Worker 留下的目录在它重新启动时删除。

一个运行在 Worker 磁盘上占用的空间（工作目录与 Task 日志合计）受 `worker.disk.quota-per-job` 限制。Worker 每五秒检查一次；
超出配额的运行在该 Worker 上的 Task 以 [`PF-RES-0004`](../reference/errors#pf-res-0004) 失败，错误中给出运行、占用的空间和配额。
这些 Task 像被取消的 Task 一样停止，工作目录被删除；Task 日志保留，仍然可以查看。Worker 上的其他运行继续。写入不会在发生时被拒绝，
因此一个运行最多会超出配额五秒内写入的量。

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `worker.disk.quota-per-job` | `10GB` | 一个运行在一个 Worker 的磁盘上最多可以占用的空间 |

本地运行把工作目录放在临时目录中，不设配额。

## ClassLoader 泄漏

每个运行都用自己的 ClassLoader 加载插件，运行在某个 Worker 上的最后一个 Task 结束后，Worker 会关闭它们。但仍可能有东西持有这些
ClassLoader：插件留下的仍在运行的线程、它注册的 JDBC 驱动、关闭钩子、ThreadLocal 或插件之外的缓存。这样的 ClassLoader 会让插件
的所有类留在内存中，积累多了 Worker 就会耗尽元空间。

Worker 在不持有它们的前提下跟踪每个已结束运行的 ClassLoader。运行结束 `worker.class-loader-leak-timeout`（默认一分钟）后仍可达的
ClassLoader 先获得一次机会：Worker 请求一次垃圾回收，几秒后再检查。届时仍然可达的 ClassLoader 会以警告记录一次，给出插件、运行、
该 Worker 上累计泄漏的 ClassLoader 数以及持有者：

- 以它作为线程上下文 ClassLoader、类由它定义，或者正在运行该插件代码的线程（同一插件为其他运行加载的代码也算在内）；
- 没有线程持有它时，警告会说明这一点：此时持有它的是插件的静态缓存或 JVM 级的注册。

```text
WARN  The class loader of plugin acme@1.2.0 for run 8f2c… was not collected 60 s after the run ended;
held by thread acme-refresher (its context class loader). The worker has 1 leaked class loader(s)
```

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `worker.class-loader-leak-timeout` | `1min` | 运行结束后，其插件的 ClassLoader 最多可以用多久被回收 |

用 `-XX:+DisableExplicitGC` 启动的 Worker 会忽略检查请求的垃圾回收，因此尚未经过完整回收的 ClassLoader 也可能被报告；这种情况下
请调大超时时间。

## 可观测性

每个 Task 随指标上报自己记账的内存；作业的 [`memoryBytes`](../reference/metrics) 是其运行中 Task 的总和。结束的 Task 不再占用内存：
写缓冲已经写空或被丢弃，网络缓冲在其他 Task 读取之前归数据交换所有，从未取走的分片被丢弃。结束时仍有记账内存的 Task 会被
Worker 作为泄漏记录到日志中，并给出占用者。

## 限制

- 堆守护只知道 Task 记账的内存；另一个运行用未记账的内存占满堆时，它会归咎错误的运行。它的动作目前只记录在 Worker 日志中，
  还没有对应的指标。Worker 仍然内存溢出时会停止，由部署环境重启。
- ClassLoader 泄漏只记录在日志中，还没有对应的指标；泄漏较多的 Worker 也还不会自动重启。
- 磁盘快满的 Worker 仍会接收新的 Task；拒绝接收以及作业磁盘占用的指标（`jobDiskUsedBytes`）在后续版本中提供。
- 被放弃的 Task 的线程会保留到 Worker 重启；Worker 因残留线程自动重启在后续版本中提供。
- Source 和 Sink 插件自身（例如它们的客户端库）占用的内存不计入记账。
