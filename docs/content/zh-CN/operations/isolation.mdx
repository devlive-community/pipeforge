作业共享集群中的 Worker：多个作业的 Task 运行在同一个 Worker 进程中，各自占用一个 Slot。一个作业不能拖垮其他作业，
因此每个 Task 都受到只让它自己失败或变慢的限制。

## 单行大小

Source 读取的每一行都按它在内存中的估算大小计量——对象头、引用以及各个值的内容，文本每个字符按两字节计。超过
`task.max-row-bytes`（默认 64MB）的行会让它的作业以 [`PF-DATA-0007`](../reference/errors#pf-data-0007) 失败，错误中给出节点、
表、大小和上限。被 Transform 变大的行在进入写缓冲之前会再检查一次；发给其他 Task 的行按编码后的大小检查。

目前整个作业失败；同一 Worker 上的其他作业继续运行。可以跳过或单独保存这类行的坏行策略会在后续版本中提供。

## Task 内存

每个 Task 对自己占用的内存记账：

| 占用者 | 计入的内容 |
|---|---|
| 写缓冲 | 等待 Sink 写线程写入的行，按估算大小 |
| 网络缓冲 | 它的输出和输入使用的缓冲，来自 Worker 的网络内存 |
| 分片队列 | 等待 Task 交给 Reader 的分片分配 |

写缓冲中等待的行受 `worker.memory.task` 限制：达到上限时，Reader 等待写线程写出一部分，这与写队列已满时的背压相同，
等待时间计入 `readerWaitMs`。没有行在等待时总会接收一行，因此超过这个上限的单行仍能通过。网络缓冲受[数据交换](../concepts/execution)
的配置限制；Task 会等待缓冲，而不会无限增长。

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `worker.memory.task` | 扣除网络内存后剩余堆的一半，按 Slot 平分，不少于 16MB | 一个 Task 为 Sink 保留的行最多占用的内存 |
| `task.max-row-bytes` | `64MB` | 单行大小上限 |
| `worker.memory.network` | 堆的 10%，64MB 到 1GB | 所有 Task 的网络缓冲 |

本地运行（`pipeforge run --local`）检查单行大小，但不限制 Task 内存。

## 插件代码

对插件的每次调用都以插件的 ClassLoader 作为线程上下文 ClassLoader。插件抛出的错误如果带有错误码则保留；否则插件有 `ErrorClassifier` 时由它转换（见[失败处理](../concepts/failure-handling)），再否则对 Source 归为
`PF-SRC-0001`、对 Sink 归为 `PF-SINK-0001`、对 Transform 归为 `PF-PLUG-0007`，并给出节点和当时的操作；插件需要却没有带上的类
（`NoClassDefFoundError` 等链接错误）也按同样方式报告，而不会让 Worker 停止。

**线程。** 插件从 Reader 或 Writer 上下文的 `threadFactory()` 获取的线程命名为 `plugin-<task>-<node>-<n>`，带有插件的
ClassLoader 和 Task 的日志，并且是守护线程。其中任何一个抛出未捕获的异常都会让 Task 失败。Task 结束时，引擎中断仍然存活的线程；
一秒后仍然存活的线程会在 Worker 日志中被报告为泄漏，并给出它停在哪里。用其他方式启动的线程不受跟踪。

**取消。** 被取消的 Task 会被唤醒，它的 Reader 和 Writer 会被要求停止阻塞的 IO。超过 `task.cancel-timeout` 仍未停止的 Task
会被中断线程；仍然不响应中断的 Task 在 `task.cancel-kill-timeout` 后被放弃：它以 [`PF-RES-0005`](../reference/errors#pf-res-0005)
失败，Slot 被释放，它的线程被报告为残留，并给出它停在哪里。Worker 上的其他作业继续运行。

| 配置项 | 文件 | 默认值 | 含义 |
|---|---|---|---|
| `task.cancel-timeout` | `master.yaml` | `30s` | 何时中断被取消的 Task 的线程；是 Master 运行的作业的默认值 |
| `task.cancel-kill-timeout` | `worker.yaml` | `3min` | 何时放弃不响应取消和中断的 Task |

本地运行在取消超时的两倍时放弃 Task。

## 可观测性

每个 Task 随指标上报自己记账的内存；作业的 [`memoryBytes`](../reference/metrics) 是其运行中 Task 的总和。结束的 Task 不再占用内存：
写缓冲已经写空或被丢弃，网络缓冲在其他 Task 读取之前归数据交换所有，从未取走的分片被丢弃。结束时仍有记账内存的 Task 会被
Worker 作为泄漏记录到日志中，并给出占用者。

## 限制

- 堆内存接近用满时让占用最多的 Task 变慢或失败的堆守护线程、ClassLoader 泄漏检测以及每个作业的磁盘配额在后续版本中提供。
- 被放弃的 Task 的线程会保留到 Worker 重启；Worker 因残留线程自动重启在后续版本中提供。
- Source 和 Sink 插件自身（例如它们的客户端库）占用的内存不计入记账。
