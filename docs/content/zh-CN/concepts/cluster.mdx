## 概述

PipeForge 集群在多台机器上运行作业。集群中有一个负责调度的 **Master**，以及任意数量运行作业 Task 的 **Worker**。
每个 Worker 提供固定数量的 **Slot**，一个 Slot 运行一个 Task 的一个并行实例。Server 把作业提交给 Master，并展示集群的运行情况。

本页说明 Master 如何管理它的 Worker：Worker 如何加入、Master 如何知道它们存活、哪些 Slot 空闲，以及 Worker 消失时会发生什么。
作业在 Task 内部如何运行见[执行](./execution)；进程之间的消息见[引擎协议](../development/engine-protocol)。

## 原理

```text
Worker                                   Master（ResourceManager）
  │── 注册：地址、Slot、标签、公钥 ──────────►│ 校验集群令牌与协议版本
  │◄── Worker ID、心跳间隔、超时 ─────────────│
  │── 心跳流 ────────────────────────────────►│ 每 5 秒：Slot 状态与运行中的 Task
  │── 提供 Slot ─────────────────────────────►│ Slot 账本
  │            …                              │
  │   （30 秒没有心跳）                         │ Worker 失联：移除，其上的 Task 失败
```

- **注册**。Worker 注册时提供 Master 与其他 Worker 访问它的地址、资源、Slot 数量、标签，以及用于加密敏感选项的公钥。
  Master 为它分配一个 ID；用原来的 ID 重新注册的 Worker 保留这个 ID，它的 Slot 重新变为空闲。
  其中的数据地址（`worker.data.port`）是其他 Worker 上的 Task 读取它的 Task 输出的地方；Master 会告诉每个 Task 它要读取的那些 Task 的数据地址。
- **心跳**。每个 Worker 与 Master 之间保持一条流，每 5 秒发送一次心跳，携带 Slot 状态和正在运行的 Task。
  Master 不认识的 Worker 发来心跳时，会被要求重新注册——例如 Master 重启之后。
- **Slot 账本**。Master 记录哪些 Slot 空闲、哪些正在运行哪个作业的 Task。调度器从账本中取空闲 Slot；
  作业可以通过标签要求只使用带有这些标签的 Worker，例如 `zone=east`。
- **调度**。作业需要的 Slot 数等于它的最大并行度（见[执行](./execution)）。调度器在带有作业所需标签的 Worker 的空闲 Slot 中
  一次性预留全部 Slot：默认的 `spread` 轮流在每个 Worker 上取一个 Slot，让作业的实例分布在尽可能多的 Worker 上；`pack`
  先占满一个 Worker 再用下一个，以减少网络传输。每个 Worker 为作业预留自己的 Slot；60 秒内没有 Task 使用的预留由 Worker 释放。
  空闲 Slot 不足的作业会排队，Slot 空出时重新尝试；超过 `scheduler.slot-request-timeout`（5 分钟）后以
  [`PF-RES-0001`](../reference/errors#pf-res-0001) 失败。
- **与 Master 失联**。在 Master 给出的超时时间内心跳都没有得到应答的 Worker，会认为自己已与 Master 断开：它取消自己的所有 Task
  （只有当前的 Master 可以控制它们），并不断尝试重新注册，默认每秒一次。Master 再次应答后，Worker 用原来的 ID 注册并提供它的 Slot。
- **Worker 失联**。30 秒没有发送心跳的 Worker 会被移出集群。Task 运行在它上面的 JobMaster 会收到
  [`PF-CLUS-0001`](../reference/errors#pf-clus-0001)，并让这些 Task 失败。

### 插件分发

插件只安装在 Master 上；Worker 按 Task 的需要获取插件。

1. Master 部署 Task 时，列出 Task 用到的每个插件及其插件包的 SHA-256。某个已安装插件第一次被部署引用时，Master 将它打包，
   并且每次都打包成相同的字节，因此哈希准确地标识了插件版本。需要[驱动插件](./plugins#驱动插件)的插件会带上驱动的插件包；接受任意驱动的插件会带上所有已安装的驱动插件。
2. 还没有该插件包的 Worker 会从 Master 分块下载。下载中断时，从已经收到的字节处继续，最多三次。
3. Worker 校验下载内容的哈希。哈希不符的插件包会被丢弃，报 [`PF-PLUG-0011`](../reference/errors#pf-plug-0011)，
   由下一个 Task 重新获取。
4. 插件包保存在 Worker 的缓存目录中，之后的运行以及 Worker 重启后都直接使用，无需再次下载。
5. 在一个 Worker 上，每次运行的每个插件都有自己的类加载器，该运行在这个 Worker 上的所有 Task 共用它。运行结束后，
   它的类加载器被关闭并可以被垃圾回收。

标记为 `builtin` 的组件随 Worker 提供，不需要插件包。

## 行为与语义

| 设置 | 默认值 | 含义 |
|---|---|---|
| 心跳间隔 | 5 秒 | Worker 发送心跳的频率；Master 也按这个频率检查失联的 Worker |
| 心跳超时 | 30 秒 | 多久没有心跳就认为 Worker 失联；必须大于心跳间隔 |
| Slot | CPU 核数 | Worker 同时运行的 Task 实例数（`worker.slots`） |
| 注册重试 | 1 秒 | 未连接的 Worker 尝试注册的频率 |
| 放置策略 | `spread` | `spread` 或 `pack`，见上文“调度” |
| Slot 等待超时 | 5 分钟 | 作业等待空闲 Slot 的最长时间（`scheduler.slot-request-timeout`） |
| 未使用的预留 | 60 秒 | 没有 Task 使用的 Slot 预留多久后由 Worker 释放 |
| 标签 | 无 | Worker 带有的键值对，例如 `zone=east`、`net=db-zone` |

- 失联的 Worker 会被立即移除，它上面的 Task 失败，错误中包含该 Worker 以及没有心跳的时长。做 [checkpoint](./checkpoint)
  的运行会在重启策略允许时，从最近完成的 checkpoint 在其他 Worker 上重启这些 Task 所在的 Region（见[失败处理](./failure-handling)）；
  不做 checkpoint 的运行随之失败。
- 失联后又恢复的 Worker 会重新注册并提供空闲的 Slot。它仍在运行的 Task 属于 Master 已不再跟踪的尝试；在 Worker 自行停止这类
  Task 之前，它们可能继续写入。
- 只有当前的 Master 能控制 Worker：已被替换的 Master 发出的请求会被 Worker 拒绝。

## 可观测性

- Master 会记录每一次注册、重新注册和 Worker 失联；Worker 失联以警告级别记录，内容为 `PF-CLUS-0001` 的错误信息。
- Worker 会记录它的注册，并以警告级别记录与 Master 失联以及没有应答的秒数。
- 因 Worker 失联而失败的作业显示 `PF-CLUS-0001`，其中包含该 Worker、它的地址以及没有心跳的秒数。

## 性能与调优

- 心跳是一条长期打开的流上的小消息；即使有上千个 Worker，Master 的开销也很小。
- 超时越短，越早发现失联的 Worker，但较长的垃圾回收停顿或短暂的网络问题也可能让仍然存活的 Worker 被移除。超时应保持为间隔的数倍。

## 排障

| 错误 | 原因与处理 |
|---|---|
| `PF-CLUS-0001` `WORKER_LOST` | Worker 已停止、长时间停顿或网络中断。请查看 Worker 日志的末尾，检查它的内存和垃圾回收。 |
| `PF-RES-0001` `SLOTS_INSUFFICIENT` | 带有作业所需标签的 Worker 上空闲 Slot 少于作业的需要。请增加 Worker 或 Slot、降低并行度、放宽标签，或者等待其他作业结束。 |
| `PF-RES-0007` `SLOT_TAKEN` | 两个作业同时预留了同一个 Slot；调度器会自动改用其他 Slot。 |
| `PF-CLUS-0005` `RPC_UNAUTHENTICATED` | Worker 的集群令牌与 Master 不同。 |
| `PF-PLUG-0010` `PLUGIN_PACKAGE_UNAVAILABLE` | Worker 无法获取插件包：Master 没有该插件、无法访问 Master，或者缓存目录无法写入。具体原因见错误信息。 |
| `PF-PLUG-0011` `PLUGIN_PACKAGE_CORRUPT` | 下载的插件包与哈希不符，已被丢弃。如果反复出现，请检查 Worker 与 Master 之间的网络。 |
| `PF-CLUS-0007` `RPC_VERSION_MISMATCH` | Worker 与 Master 的主版本不同；整个集群请使用同一个发行版本。 |

## 限制

- Master 通过它的 RPC 接收运行；服务和 `pipeforge run` 向集群提交作业会在分布式运行时的后续步骤中提供，在此之前以本地模式运行作业。
- 只有一个 Master；可以接管的备用 Master 随故障恢复一起提供。
- Master 和 Worker 通过发行包中的脚本启动；见[部署](../operations/deployment)。
- 资源组会被记录，但还没有用来限制一个组占用的 Slot 数量。

## 版本

自 0.1.0 起作为分布式运行时的一部分提供。
