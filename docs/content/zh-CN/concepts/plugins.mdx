## 概述

每一个 Source、Sink、Transform 和 Catalog 都是插件。插件以插件包的形式安装，按需加载，彼此隔离：每个插件版本有自己的类加载器，
因此两个插件可以在同一个进程中使用同一个库的不同版本，例如两个不同版本的 JDBC 驱动。

## 原理

### 发现

启动时 PipeForge 扫描插件目录。插件可以是 zip 包，也可以是包含 `plugin.yaml` 和 `lib/` 的解压目录。zip 包会被解压到以内容哈希命名的缓存目录中。
为其他主版本的连接器 API 构建的插件会被标记为不可用，并给出原因。

### 类加载器隔离

```text
JDK
 └── 引擎类加载器：引擎、pipeforge-api、错误码、SLF4J
       ├── 插件类加载器：mysql@1.0.0   （child-first）
       ├── 插件类加载器：kafka@1.2.0   （child-first）
       └── 插件类加载器：doris@1.0.0   （child-first）
```

插件类加载器先在插件自己的 jar 中查找类，找不到才交给引擎。以下包是例外，总是由父加载器加载，保证引擎和插件使用同一套类型：
`java.*`、`javax.*`、`jdk.*`、`org.devlive.pipeforge.api.*`、`org.devlive.pipeforge.common.*`、`org.slf4j.*` 和 `org.jspecify.*`。

### 租约与卸载

同一个插件版本的所有使用者共用一个类加载器。作业为用到的每个插件申请一个**租约**，结束时释放；最后一个租约释放后，类加载器被关闭并可以被垃圾回收，
长期运行的 Worker 不会因此泄漏内存。

### 调用边界

对插件代码的调用都经过插件的调用器：把插件类加载器设置为线程上下文类加载器；把失败包装成带插件名和操作名的错误（`PF-PLUG-0007`）；
控制类操作超过超时时间时中断它（`PF-PLUG-0006`）。

### 禁止的调用

加载插件之前，会检查插件的 jar 中是否调用了影响整个进程中所有作业的方法：`System.exit`、`Runtime.halt`、修改系统属性、默认时区或区域设置、
安全提供者、标准输入输出流或 JVM 级的处理器。这样的插件会以 `PF-PLUG-0005` 被拒绝加载。

## 快速上手

把插件包复制到插件目录，然后在作业中用组件标识引用它：

```bash
cp greeting-plugin-1.0.0.zip $PIPEFORGE_HOME/plugins/
```

```yaml
source:
  - id: hello
    type: greeting          # plugin.yaml 中声明的标识
```

## 配置

| 字段 | 位置 | 含义 |
|---|---|---|
| `plugin` | 作业节点 | 固定使用某个插件：`greeting` 或 `greeting@1.0.0`；不写时使用已安装的最高版本 |
| `plugin.paths` | 引擎配置 | 额外的插件目录 |

## 示例

### 两个版本并存

同时安装 `greeting-plugin-1.0.0.zip` 和 `greeting-plugin-1.1.0.zip` 后，作业默认使用 1.1.0；还没有用新版本测试过的作业可以继续使用旧版本：

```yaml
source:
  - id: hello
    type: greeting
    plugin: greeting@1.0.0
```

### 两个插件的依赖冲突

MySQL 插件自带某个版本的 JSON 库，Kafka 插件自带另一个版本，两者可以在同一个作业中运行而不冲突，因为每个库都由各自插件的类加载器加载。

```yaml
source:
  - id: orders
    type: mysql-cdc
sink:
  - id: events
    type: kafka
    inputs: [orders]
```

## 行为与语义

- 没有固定版本时使用语义化版本最高的插件；预发布版本排在对应的正式版本之前。
- 多个插件提供同一个标识时，作业必须用 `plugin` 指定其中一个（`PF-PLUG-0008`）。
- 正在运行的作业继续使用启动时的插件版本，即使安装了更新的版本。

## 排障

| 错误 | 原因与处理 |
|---|---|
| `PF-PLUG-0001` | 没有已安装的插件提供该组件；安装插件或检查标识。 |
| `PF-PLUG-0002` | 插件为其他 API 主版本构建；安装与当前版本匹配的构建。 |
| `PF-PLUG-0004` | 插件包不完整，例如 `lib/` 为空。 |
| `PF-PLUG-0005` | 插件调用了影响整个 JVM 的操作；应改为通过选项传递设置。 |
| `PF-PLUG-0006` | 插件调用没有按时完成；检查外部系统。 |
| `PF-PLUG-0008` | 多个插件提供该标识；在节点上设置 `plugin`。 |

## 限制

- 插件分发到各个 Worker 的能力随分布式运行时（M1 里程碑）提供；本地运行从本地插件目录加载。
- 未被回收的类加载器的泄漏报告随 M2 的隔离能力提供。

## 版本
