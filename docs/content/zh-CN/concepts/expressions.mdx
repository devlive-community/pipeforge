## 概述

作业中需要计算一个值或一个条件的地方（`filter` 和 `router` 的条件、`field-mapper` 的 `expr`、数据质量规则、Join 条件、SQL 作业）
都使用同一套表达式语言，也就是 SQL 的标量表达式。因此 YAML 作业和 SQL 作业的行为完全一致。

表达式用于逐行计算。聚合和窗口属于有状态算子，另有说明。

## 原理

1. **解析**：用 Apache Calcite 的 SQL 解析器解析文本。
2. **分析**：按输入 Schema 解析列名，检查操作数类型并插入隐式转换。结果类型在计划阶段就确定，错误在作业运行前报告，并给出行号和列号（`PF-PLAN-0007`）。
3. **编译**：一个算子中的所有表达式用 Janino 一起编译成一个 Java 类。短路运算按需求值；确定性的子表达式被多次使用时
   （无论在同一个表达式中还是跨表达式），每行只计算一次。
4. **运行**：除零等运行时错误按节点的 `on-error` 处理。

另有一个语义完全相同的解释器；每次构建都会生成数千个随机表达式，比较编译执行和解释执行的结果。

## 快速上手

```yaml
transform:
  - name: enrich
    type: field-mapper
    fields:
      - { expr: "amount * qty", to: total }
      - { expr: "CASE WHEN qty = 0 THEN NULL ELSE amount / qty END", to: unit_price }
      - { expr: "country IN ('DE', 'FR')", to: is_eu }
```

## 配置

| 选项 | 位置 | 取值 | 默认值 |
|---|---|---|---|
| `on-error` | 每个使用表达式的节点 | `dirty`、`null`、`fail` | `dirty` |
| `env.timezone` | 作业 | IANA 时区，例如 `Asia/Shanghai` | `UTC` |

| `on-error` | 行为 |
|---|---|
| `dirty` | 该行作为坏行，按脏数据策略处理（`PF-DATA-0006`） |
| `null` | 表达式结果为 NULL，行继续处理，并记录失败次数 |
| `fail` | 本次运行失败（`PF-DATA-0006`） |

完整语法见[表达式语法参考](../reference/expression-syntax)。

## 示例

### 保护除法

```sql
-- qty 为 0 时得到 NULL 而不是报错
amount / NULLIF(qty, 0)

-- 指定默认值
CASE WHEN qty = 0 THEN 0 ELSE amount / qty END
```

### 安全地转换文本

```sql
TRY_CAST(raw_price AS DECIMAL(12, 2))     -- raw_price 不是数字时为 NULL
CAST(created AS TIMESTAMP(3))             -- 文本不是时间戳时报错
```

## 行为与语义

- **类型在运行前确定。** 整数和字符串之间不会悄悄转换：`'10' > 9` 会被拒绝，应写成 `CAST('10' AS INT) > 9`。
- **隐式转换不丢失信息**：较窄的整数转为较宽的整数、DECIMAL 或 FLOAT64；DECIMAL 转为更宽的 DECIMAL 或 FLOAT64；FLOAT32 转为 FLOAT64；DATE 转为 TIMESTAMP。
- **整数除法是精确的**：`7 / 2` 等于 `3.5`（DECIMAL）。整数溢出和超过 38 位的 DECIMAL 都是运行时错误，不会回绕或截断。
- **三值逻辑**：`NULL AND FALSE` 为 FALSE，`NULL AND TRUE` 为 NULL，`NULL OR TRUE` 为 TRUE。与 NULL 比较的结果为 NULL；
  `IS [NOT] DISTINCT FROM` 把 NULL 当作普通值。条件结果为 NULL 时视为不成立。
- **按需求值**：`CASE`、`IF`、`COALESCE`、`AND`、`OR` 只计算需要的部分，因此条件中的保护可以保住分支。
- **时区**：`TIMESTAMP` 与 `TIMESTAMP_LTZ` 之间的转换、把 `TIMESTAMP_LTZ` 转为文本，以及日期时间函数（`CURRENT_DATE`、`NOW()`、
  `TO_TIMESTAMP_LTZ`、`HOUR` 等）都按作业时区进行。
- **运行时间**：`RUN_START_TIME()` 是本次运行开始的时刻，对每一行和每次重试都相同，因此是确定的；`NOW()` 和 `CURRENT_TIMESTAMP`
  每次调用都读取时钟。
- **函数**：[函数参考](../reference/functions)列出了全部内置函数及其签名和 NULL 行为。除非另有说明，任一参数为 NULL 时函数返回 NULL。
  非法参数（例如 `SUBSTRING(s, 0)` 或不存在的日期）是运行时错误，按 `on-error` 处理。
- **确定性**：每个函数都标注是否确定。不确定的调用不会在表达式之间共享，也不会下推到 Source。
- **安全**：表达式不能访问文件、网络、反射和系统属性；正则表达式使用线性时间的 RE2。

## 性能与调优

表达式以字节码执行，没有需要调整的参数。确定性的子表达式重复书写不会带来额外开销。结构相同、只有字面量不同的表达式共用一个生成的类，
因此大量并行实例不会重复编译。

## 排障

| 错误 | 含义 |
|---|---|
| `PF-PLAN-0007` … `cannot compare STRING(2) with INT32` | 字符串和数字之间需要显式 `CAST` |
| `PF-PLAN-0007` … `column 'nme' does not exist; did you mean 'name'?` | 列名拼写错误 |
| `PF-PLAN-0007` … `column 'NAME' is ambiguous` | 两列只有大小写不同；用反引号写明要用哪一列：`` `Name` `` |
| `PF-DATA-0006` … `division by zero` | 用 `NULLIF` 或 `CASE` 保护，或者设置 `on-error` |
| `PF-DATA-0006` … `numeric overflow` | 改用更宽的类型，例如 `CAST(x AS BIGINT)` |

## 限制

- 不支持 `INTERVAL` 值；日期运算请使用 `DATE_ADD`、`DATE_SUB` 和 `TIMESTAMPDIFF`。
- 暂不支持自定义函数。
- 子查询不是表达式，`IN` 只接受值列表。
- 不支持 `BETWEEN SYMMETRIC`。
