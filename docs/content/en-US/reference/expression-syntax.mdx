## Literals

| Type | Written as |
|---|---|
| String | `'abc'`; a quote inside is doubled: `'it''s'` |
| Integer | `42`, `-7` — `INT32`, or `INT64` when it does not fit |
| Decimal | `3.14` — `DECIMAL(3, 2)` |
| Floating point | `1e6` — `FLOAT64` |
| Boolean | `TRUE`, `FALSE` |
| NULL | `NULL` |
| Date and time | `DATE '2026-11-07'`, `TIME '12:30:00'`, `TIMESTAMP '2026-11-07 12:30:00.123'` |
| Instant | `TIMESTAMP_LTZ '2026-11-07 12:30:00+08:00'` (the offset is required) |
| Binary | `X'6869'` |
| Array, map | `ARRAY[1, 2, 3]`, `MAP['k1', 1, 'k2', 2]` |

## Identifiers

- Columns are written as they are and match case-insensitively. Quote a name with backticks when it
  contains special characters, is a keyword, or must match case exactly: `` `order-id` ``, `` `Name` ``.
- Nested values: `address.city` (ROW field), `tags[1]` (array element, 1-based), `attrs['color']`
  (map value). A missing element or key gives NULL.
- Pseudo-columns describe the row itself:

| Pseudo-column | Value |
|---|---|
| `$table` / `$db` / `$schema` | Table, database and schema of the row |
| `$rowkind` | `'INSERT'`, `'UPDATE_BEFORE'`, `'UPDATE_AFTER'` or `'DELETE'` |

## Operators

From highest to lowest precedence:

| Precedence | Operators |
|---|---|
| 1 | `.` (field), `[]` (element) |
| 2 | unary `+`, `-` |
| 3 | `*`, `/`, `%` |
| 4 | `+`, `-`, `\|\|` (string concatenation) |
| 5 | `=`, `<>`, `!=`, `<`, `<=`, `>`, `>=`, `IS [NOT] DISTINCT FROM` |
| 6 | `IS [NOT] NULL`, `IS [NOT] TRUE`, `IS [NOT] FALSE`, `[NOT] BETWEEN`, `[NOT] IN`, `[NOT] LIKE`, `[NOT] RLIKE` |
| 7 | `NOT` |
| 8 | `AND` |
| 9 | `OR` |

- `LIKE` matches the whole string: `%` is any sequence, `_` one character; `ESCAPE '!'` makes the
  next character literal.
- `RLIKE` is true when an RE2 regular expression matches part of the string; anchor with `^` and `$`.
- `/` on integers gives an exact DECIMAL; `%` keeps the integer type.

## Conditional expressions

| Expression | Result |
|---|---|
| `CASE WHEN c1 THEN r1 [WHEN …] [ELSE e] END` | The first result whose condition is TRUE, else `e` or NULL |
| `CASE x WHEN v1 THEN r1 … END` | Same as `CASE WHEN x = v1 THEN r1 … END` |
| `IF(c, a, b)` | `a` when `c` is TRUE, otherwise `b` |
| `COALESCE(a, b, …)` | The first non-NULL argument |
| `IFNULL(a, b)` | `COALESCE(a, b)` |
| `NULLIF(a, b)` | NULL when `a = b`, otherwise `a` |

The results of a conditional expression are converted to their common type.

## Function calls

Functions are called as `NAME(arguments)`; names are case-insensitive. The
[function reference](./functions) lists every built-in function. A few calls use SQL keywords:

| Form | Same as |
|---|---|
| `SUBSTRING(s FROM 2 FOR 3)` | `SUBSTRING(s, 2, 3)` |
| `TRIM([BOTH \| LEADING \| TRAILING] [chars] FROM s)` | `TRIM(s, chars)`, `LTRIM(s, chars)`, `RTRIM(s, chars)` |
| `POSITION(part IN s)` | `INSTR(s, part)` |
| `EXTRACT(unit FROM t)` | `YEAR(t)`, `MONTH(t)`, `DAYOFMONTH(t)`, … |
| `TIMESTAMPDIFF(unit, start, end)` | — (the unit is a keyword such as `MONTH`) |
| `CURRENT_DATE`, `CURRENT_TIMESTAMP` | `NOW()` for the timestamp; written without parentheses |

Arguments are converted implicitly to the parameter types under the same rules as operators. When a
function is overloaded, the narrowest matching overload is used: `ABS(i)` on an `INT32` stays `INT32`.

## Casts

```sql
CAST(value AS type)       -- fails when the value cannot be converted
TRY_CAST(value AS type)   -- NULL when the value cannot be converted
```

Types can be written as [logical types](../concepts/data-model), exactly as in job definitions
(`INT64`, `STRING(20)`, `BYTES(16)`, `DECIMAL(10, 2)`, `TIMESTAMP_LTZ(3)`, `ARRAY<INT64>`,
`MAP<STRING, INT64>`, `ROW<a INT32, b STRING>`), or with SQL names (`BIGINT`, `VARCHAR(20)`,
`NUMERIC(10, 2)`, `TIMESTAMP(3) WITH LOCAL TIME ZONE`, `BIGINT ARRAY`).

| From | To | Rule |
|---|---|---|
| String | number, boolean | Leading and trailing spaces are ignored; booleans accept `true/false`, `t/f`, `yes/no`, `1/0` |
| String | date and time | ISO 8601: `2026-11-07`, `12:30:00`, `2026-11-07 12:30:00.123` (space or `T`) |
| String | `TIMESTAMP_LTZ` | With an offset (`+08:00`, `Z`) it is exact; without one, local time in the job time zone |
| Number | integer | Rounded half up; out of range is an error |
| Number | `DECIMAL(p, s)` | Rounded half up to `s` digits; more than `p` digits is an error |
| Anything | `STRING(n)` | Longer text is cut to `n` characters |
| `TIMESTAMP` | `DATE`, `TIME` | Keeps the date or the time of day |

Tools that take values as text or show results as text, such as the expression endpoint of the
server, convert them the same way: text to a column type like `CAST(text AS type)`, results like
`CAST(value AS STRING)`, except that booleans are written `TRUE` / `FALSE`, decimals without an
exponent and arrays as `[a, b]`.

## Types and implicit conversion

Operands of different types are converted to a common type only when no information is lost:

| From | Converted implicitly to |
|---|---|
| `INT8` → `INT16` → `INT32` → `INT64` | a wider integer, `DECIMAL`, `FLOAT64` |
| `DECIMAL(p, s)` | a wider `DECIMAL`, `FLOAT64` |
| `FLOAT32` | `FLOAT64` |
| `DATE` | `TIMESTAMP` (midnight) |
| `STRING(n)` | `STRING(m)` with m ≥ n |

Strings are never converted to numbers or dates implicitly. Results of DECIMAL arithmetic follow the
SQL rules for precision and scale, capped at 38 digits:

| Operation | Precision | Scale |
|---|---|---|
| `a + b`, `a - b` | max(p1 − s1, p2 − s2) + s + 1 | s = max(s1, s2) |
| `a * b` | p1 + p2 + 1 | s1 + s2 |
| `a / b` | p1 − s1 + s2 + s | s = max(6, s1 + p2 + 1) |
