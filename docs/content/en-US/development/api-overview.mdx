## One dependency

Plugins depend on `org.devlive.pipeforge:pipeforge-api` only. It does not depend on any engine;
besides the JDK it brings `pipeforge-common` (error codes) and JSpecify (nullness annotations). The
same plugin can therefore run on the PipeForge engine and, later, on Flink or Spark.

```xml title="pom.xml"
<dependency>
  <groupId>org.devlive.pipeforge</groupId>
  <artifactId>pipeforge-api</artifactId>
  <version>0.1.0</version>
  <scope>provided</scope>
</dependency>
```

## Sources

A source has one **enumerator** that discovers splits and many parallel **readers** that read them.
Readers pull splits: when a reader finishes a split it asks for the next, so fast readers do more
work. Batch, streaming and CDC sources implement the same interface and differ in
`boundedness()` and their splits.

```java
public interface SourceReader<SplitT extends SourceSplit> extends AutoCloseable {
    void start() throws Exception;
    void addSplits(List<SplitT> splits);
    void notifyNoMoreSplits();
    PollStatus pollNext(ReaderOutput output) throws Exception; // never block for long
    List<SplitT> snapshotState(long checkpointId);           // splits with their progress
}
```

`pollNext` returns `NOTHING_AVAILABLE` instead of blocking; the engine backs off and polls again.
The state of a split records the position already handed to the output, so a restored reader
continues exactly there.

## Transforms and sinks

A `Transform` derives its output tables while planning (`transformSchema`) and processes rows one
by one (`process(row, out)`); schema changes go through `transformSchemaChange`.

A `Sink` validates its input tables while planning and creates writers. Writers `write`, `flush`
and, for exactly-once delivery, produce committables in `prepareCommit`; a `SinkCommitter` or
`GlobalCommitter` commits them after the checkpoint completes.

## Expressions

Components that take expressions from the user, such as the `expr` of a field mapping or a filter
condition, do not ship their own parser: `context.expressions()` hands them the
[expression language](../concepts/expressions) of the engine, with the same type rules and
functions as everywhere else in PipeForge.

```java
// while planning, in the factory: types are known before any data is read
ExpressionCompiler expressions = factoryContext.expressions();
ExpressionInfo info = expressions.analyze(List.of("amount * qty"), table.columns()).get(0);
info.type();           // DECIMAL(21, 2)

// at run time, in Transform.open: one evaluator per parallel instance
RowEvaluator evaluator = context.expressions().compile(List.of("amount * qty"), columns, OnError.DIRTY);
Object[] values = new Object[evaluator.size()];
evaluator.evaluate(row, values);
```

- An expression that does not parse or type-check fails planning with `PF-PLAN-0007`, the line
  and column of the problem, and the node in the scope.
- Expressions compiled together share their common subexpressions. The evaluator is not
  thread-safe.
- `OnError` decides what a failure while evaluating does (`dirty`, `null` or `fail`); expose it as
  the component's `on-error` option.
- `RUN_START_TIME()` is the same in every task of a run, and dates and times follow the job's
  `env.timezone`.

## Functions

Functions are annotated Java methods. The built-in functions are declared this way, and function
plugins will use the same contract from `api.function`, so a plugin depends on `pipeforge-api`
only. Installing function plugins arrives in a later version; the contract below is what they will
be written against.

```java
public final class CardFunctions {

    @ScalarFunction(name = "mask_card")                // registered in the plugin's namespace: acme.mask_card
    public static String maskCard(String cardNo) {     // a NULL argument returns NULL without a call
        return "****" + cardNo.substring(Math.max(0, cardNo.length() - 4));
    }

    @ScalarFunction(name = "with_rate")
    @Returns("DECIMAL(18, 2)")                         // the Java type is not precise enough
    public static BigDecimal withRate(@Param("DECIMAL(16, 2)") BigDecimal amount, int rate) {
        return amount.multiply(BigDecimal.valueOf(rate));
    }

    @ScalarFunction(name = "local_day")
    public static LocalDate localDay(FunctionContext context, Instant at) {  // the context is injected
        return at.atZone(context.timeZone()).toLocalDate();
    }
}
```

| Contract | Meaning |
|---|---|
| `@ScalarFunction(name, deterministic = true, nullOnNull = true)` | On a public method; methods with the same name are overloads. With `nullOnNull` a NULL argument gives NULL without calling the method; without it the parameters need reference types. A function is deterministic only when all its overloads are |
| `@Returns("…")` | The result type: a type such as `DECIMAL(18, 2)`, `$n` for the type of argument `n` (from 0), `$n:integral` for a DECIMAL argument without fractional digits. Without it the type follows from the Java return type |
| `@Param("…")` | The type of a parameter; arguments are cast to exactly this type, and arguments that do not fit are rejected while planning. Without it, a `BigDecimal` or `String` parameter accepts any DECIMAL or STRING as it is |
| `FunctionContext` | As first parameter: the job time zone, the run start time, the processing time, the job and the function parameters configured for the job |
| `FunctionLifecycle` | Needed for instance methods: every parallel instance creates one object, calls `open(context)` before the first row and `close()` after the last; a failure is reported as `PF-PLUG-0007` |

Java types map to logical types as in rows: `String` → `STRING`, `int` → `INT32`, `long` → `INT64`,
`double` → `FLOAT64`, `boolean` → `BOOLEAN`, `BigDecimal` → `DECIMAL`, `LocalDate` → `DATE`,
`LocalTime` → `TIME`, `LocalDateTime` → `TIMESTAMP`, `Instant` → `TIMESTAMP_LTZ`, `byte[]` → `BYTES`.

## Options

Each factory declares its options and the rules between them in an `OptionRule`. The same rule
validates jobs while planning, renders the form in the UI and generates the plugin page.

```java
static final Option<String> URL = Options.key("url").stringType().noDefault().withDescription("JDBC URL");
static final Option<Integer> FETCH_SIZE =
        Options.key("fetch-size").intType().defaultValue(1000).withRange(1, null).withGroup("throughput");

@Override
public OptionRule optionRule() {
    return OptionRule.builder()
            .required(URL)
            .optional(FETCH_SIZE)
            .exclusive(QUERY, TABLE)                                  // exactly one of them
            .conditional(SPLIT_STRATEGY, Strategy.RANGE, SPLIT_COLUMN) // RANGE needs split-column
            .nativeNamespaces("jdbc.properties")                      // passed through unchecked
            .build();
}
```

Option types are `stringType`, `intType`, `longType`, `doubleType`, `booleanType`, `durationType`
(`30s`, `5m`), `enumType`, `listType` (a list of plain values, or a comma-separated string),
`mapType` (nested keys, also written dotted) and `objectListType`: a list of objects with plain
values, such as the entries of a field mapping (`[{ from: id, to: order_id }]`), read as
`List<Map<String, String>>`.

Validation reports missing options as `PF-CONF-0001` and invalid values (type, range, exclusive
groups, unknown keys with a suggestion) as `PF-CONF-0002`. Sensitive options are masked in errors.

## Factories

Factories are found with `java.util.ServiceLoader` from the plugin's class loader. A factory has an
`identifier()` — the name used in jobs — and an `optionRule()`, and creates its component from a
`FactoryContext` with validated options, native configuration, job information and input tables.

## Stability

Every public type is annotated:

| Annotation | Promise |
|---|---|
| `@Stable` | Binary compatible within a major version |
| `@Evolving` | May change in a minor version |
| `@Internal` | No promise; not for plugins |

`ApiVersion.current()` returns the API version at run time; a plugin declares the major version it was built for (`ApiVersion.descriptorForm()`, e.g. `0.x`) and the engine refuses plugins built for another major version.

New interface methods always get a default implementation. The build compares the API with the
last release using japicmp and fails on incompatible changes; a test checks that every public type
carries one of the annotations.
