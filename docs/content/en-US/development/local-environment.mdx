## Overview

The `dev/` directory contains a docker compose project with every service that PipeForge's
examples and integration tests need: databases prepared for change data capture, object
storage, a proxy for fault injection and a monitoring stack. Use it to try examples, debug a
connector or run tests against real services. It is not meant for production or benchmarks.

## Quick start

Requirements: Docker with Compose v2.

```bash
pipeforge dev up         # start everything and wait until all services are healthy
./dev/check.sh           # verify binlog, logical decoding, proxies and monitoring
pipeforge dev status     # state, health and ports of every service
pipeforge dev down       # stop; add --volumes to delete the data as well
```

Start object storage as well with `pipeforge dev up --s3`, or a single service and what it
depends on with `pipeforge dev up mysql`.


### The dev commands

| Command | What it does |
|---|---|
| `pipeforge dev up [--s3] [--timeout 5m] [<service>...]` | Starts the services and waits until they are healthy, then shows the status. The output of docker compose goes to the standard error. |
| `pipeforge dev status` | Shows every service. Exits with 0 when all of them are healthy, and with 1 when nothing runs or a service is not healthy, so scripts can wait for it. |
| `pipeforge dev down [--volumes]` | Stops every service, those of the `s3` profile included. |

All of them accept `-o json` and `--dir <dir>`. Without `--dir`, the command uses `dev/` of the
source checkout around the current directory, then `dev/` of the installation: the distribution
contains the same environment, so plugin authors can use it without a checkout. A one-off service
whose name ends in `-init`, such as `minio-init`, counts as healthy once it has exited with 0.

Without the command, the scripts do the same: `./dev/up.sh [--s3] [<service>...]`,
`./dev/down.sh [--volumes]`.

## Configuration

| Service | Host port | Purpose | Credentials |
|---|---|---|---|
| MySQL 8.4 | 33306 | Binlog in ROW format with GTID, ready for CDC | `pipeforge` / `pipeforge` |
| PostgreSQL 16 | 35432 | `wal_level=logical`, user has the replication role | `pipeforge` / `pipeforge` |
| MinIO (profile `s3`) | 39000, console 39001 | S3-compatible storage, buckets `pipeforge` and `pipeforge-checkpoints` | `pipeforge` / `pipeforge-secret` |
| Toxiproxy | API 38474, MySQL 43306, PostgreSQL 45432 | Inject latency, bandwidth limits and disconnects | — |
| Prometheus | 39090 | Scrapes a PipeForge process on the host at port 9250 | — |
| Grafana | 33000 | Prometheus data source provisioned | `admin` / `pipeforge` |

Every host port can be changed: copy `dev/.env.example` to `dev/.env` and edit the values.
The MinIO project no longer publishes community images on Docker Hub; set
`PIPEFORGE_MINIO_IMAGE` to an image that contains both the `minio` server and the `mc` client.

Sample data is created on first start: `pipeforge.customers` and `pipeforge.orders` in MySQL,
`inventory.products` and an empty `sync` schema in PostgreSQL.

## Examples

### Read the MySQL binlog

The database is ready for CDC without further setup:

```bash
docker compose -f dev/docker-compose.yaml exec mysql \
  mysql -upipeforge -ppipeforge -e "SHOW BINARY LOG STATUS"
```

### Simulate a slow or broken network

Connect a job to the Toxiproxy port instead of the database port, then add a toxic:

```bash
# 500 ms latency on every MySQL response
curl -s -X POST localhost:38474/proxies/mysql/toxics \
  -d '{"type":"latency","attributes":{"latency":500}}'

# cut the connection, then restore it
curl -s -X POST localhost:38474/proxies/mysql -d '{"enabled":false}'
curl -s -X POST localhost:38474/proxies/mysql -d '{"enabled":true}'
```

## Troubleshooting

| Problem | Solution |
|---|---|
| `port is already allocated` | Another process uses the port. Change it in `dev/.env`. |
| A service never becomes healthy | `pipeforge dev status` names it; run `docker compose -f dev/docker-compose.yaml logs <service>`. |
| `PF-CLUS-0003` Docker is not available | Start Docker; `docker version` and `docker compose version` must both work. |
| `PF-CONF-0008` … `pass --dir` | The command found no environment: run it inside the source checkout, from an installation, or pass `--dir`. |
| Sample data is missing | Init scripts only run on an empty volume: `pipeforge dev down --volumes`, then start again. |
| `pipeforge dev up --s3` cannot pull the MinIO image | Set `PIPEFORGE_MINIO_IMAGE` in `dev/.env` to an image you can pull. |

## Limitations

- Kafka, Hive Metastore, HDFS and Doris will be added together with their connectors.
- The credentials are fixed and public; never expose these ports outside your machine.
